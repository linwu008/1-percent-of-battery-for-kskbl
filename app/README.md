# 1% Battery · v0.3.0

灾后资源决策模拟器。手机只剩 **1.000%** 电量，你要在 **8~12 步**（具体几步不告诉你）里决定这点电花在哪儿。
每一步固定推进 **15 分钟**——就算你什么都不做，电池也在自己往下掉。
结算不再给分数，而是给一个**存活概率**：你有多大可能被找到、被救出、并且撑到那一刻。

## 启动

需要 Node.js 24 或更新的兼容版本。测试环境为 Node 24.20.0、Windows、Edge。

```powershell
cd app
npm ci
npm run dev
```

浏览器打开终端给出的本地地址，默认 http://127.0.0.1:5173 。运行无需云 API、账号、定位或真实短信权限。依赖首次安装需要网络。

## 一局怎么走

1. **先看清处境**：开局逐字打出这一局的灾难现场——发生了什么、天亮不亮、身上有没有伤、有没有纸笔、信号还在不在，最后讲清楚任务是什么。测试玩家看不懂题，多半不是题难，是不知道自己站在哪儿。
2. **选天赋**：看到本局的世界（灾种 / 信号 / 伤势 / 温度 / 时段 / 随身），再从随机抽到的三个天赋里三选一。
3. **走 8~12 步**：从 **130 道题库**里按本局编号（seed）抽取，早 / 中 / 晚三段分配。界面只显示「第 n 步」，不显示总数。
4. **结算**：存活概率、三条曲线、权重贡献、完整公式、逐题复盘、导出 JSON。

中途随时可以**放弃这一局并重开**，本局不计入记录。

固定案例用于演示与回归：**案例 A**（局部有网、擦伤、深夜、有纸笔，9 步）、**案例 B**（彻底断网、持续失血、严寒、两手空空，11 步）。案例连题目顺序都固定，所以演示和比较能对得上。

## 电量是变量，不是常量

电量内部以 **0.001%** 记账，满值 1000 = 屏幕上的 1.000%。选项标价 0~260，但**实际耗电会被环境改写**：

```
实际耗电 = 名义标价 × 环境倍率 × 1.3（整体倍率），再算天赋折扣
环境倍率 = 温度系数（阴凉 1.00 / 闷热 1.10 / 严寒 1.15 / 炎热 1.25）
          × 信号系数（仅亮屏类：局部 1.00 / 微弱 1.15 / 时断时续 1.20 / 断网 1.30）
```

**自然损耗**：每一步 15 分钟，电池固定掉一格，不操作也掉：

```
每步自然损耗 = 14 × 温度系数 × 信号系数
温度：阴凉 1.00 / 闷热 1.15 / 严寒 1.30 / 炎热 1.55
信号：局部 1.00 / 微弱 1.20 / 时断时续 1.35 / 断网 1.45
```

炎热 + 断网是最狠的组合——每步自然就掉 31 格（0.031%），什么都不做，十步之后一半的电就没了。

电量归零后，**不耗电的选项仍然选得动**，但拿到的都是些小成果；想再做什么大动作就没门了。这是设计好的：破产不是死局，是只剩小动作。

六类成果各有**门槛**（位置 4 / 人数 2 / 光信号 3 / 传达 2 / 回联 4 / 接力 3），门槛刻意高于「一次不耗电操作能拿到的点数」——否则全靠免费选项就能凑齐成果，1% 就成了摆设。

## 存活概率：三段相乘

分数换成了概率，因为「省电胜利」这件事不值得宣传，而「活下来的可能性」才是这批决策真正的产出。

```
P(存活) = P(被发现) × P(被救出) × P(撑到救援)

P(被发现) = 0.18 + 0.85 ×（被发现贡献 ÷ 15），上限 0.95
P(被救出) = 0.22 + 0.78 ×（被救出贡献 ÷ 10），上限 0.95
P(撑到救援) = 0.66 + 0.42 × 剩余电量比例 − 0.012 × 已走步数
              − 伤势惩罚 − 温度惩罚 − 关机惩罚（电量归零 0.25），下限 0.03
```

伤势惩罚：无 0 / 擦伤 0.02 / 疑似骨折 0.08 / 持续失血 0.16。
温度惩罚：阴凉 0 / 闷热 0.02 / 炎热 0.06 / 严寒 0.10。

前两段的「贡献」怎么算，就是**权重档位**：

```
每一步的贡献 = 该成果的实际点数 × 该选项的档位倍率
被发现贡献 = Σ（位置送达 / 光信号起作用 / 人数送达 的点数 × 倍率）
被救出贡献 = Σ（安排已传达 / 回联确认 / 接力送达 的点数 × 倍率）
```

| 档位 | 倍率 | 判定（题库没写档位时的默认规则） |
| --- | --- | --- |
| 最重要 | ×3 | 名义成本 ≥ 110，且有收益 |
| 较重要 | ×2 | 名义成本 1~109，且有收益 |
| 不重要 | ×1 | 完全不耗电，或压根没有收益 |

同样是 2 点：一个免费的「不重要」动作只算 2 分，一个掏电的「最重要」动作算 6 分。结算页把三档的贡献分别列出来，并给出完整公式，可以自己复算。

## 三条曲线：你偏离在哪一步

结算页画一张弧线图，三条线同屏：

- **事后最优**（虚线）：知道本局全部赌运之后能达到的理论上限，由定向搜索（beam 20 × 三个天赋）算出。**它不是标准答案**——当时没人知道那些信息。它的唯一作用是让人看见自己哪一步偏了，并标出偏离最多的那一步。
- **你**：每一步结束时的存活概率。
- **Ghost**：同批题、同赌运、按性格花钱的另一条路。

纵轴是「按当时手上的东西算，能活下来的概率」，两条线之间的落差就是那一步的选择造成的偏差。

## 实测（60 个种子 × 三种典型打法）

| 打法 | 存活概率均值 | 区间 | 结束时剩余电量 | 中途只能空转的局数 |
| --- | --- | --- | --- | --- |
| 激进（每步挑最高收益） | 16.2% | 1.2 ~ 42.7% | 23 / 1000 | 44 / 60 |
| 保守（每步挑最便宜） | 25.5% | 7.5 ~ 48.5% | 385 / 1000 | 13 / 60 |
| 性价比（单位电量收益最高） | 26.3% | 3.8 ~ 51.1% | 338 / 1000 | 14 / 60 |
| 事后最优参考线 | 41.3% | 17.2 ~ 65.1% | — | — |
| 什么都不做 | 约 3% | — | 约 820 / 1000 | — |

读数：激进派把成果拉满（被发现贡献 19.3）但把电烧光，最后一段「撑到救援」崩掉；保守派和性价比派活得更久。三者都拿不到满值成果，也都没有一种打法通吃。题数在 8~12 上分布均匀（60 局：8 题 9 局 / 9 题 17 局 / 10 题 11 局 / 11 题 11 局 / 12 题 12 局）。

## 为什么没有唯一最优解

- **环境耦合**：同一个选项带 `env` 规则，世界满足某条件时收益增减。断网时「再发一次短信」是纯浪费，局部有网时它是救命的一步。题库里带环境修正的选项占比有测试兜底。
- **条件收益与赌运**：带「不确定」标签的选项成败由本局编号预先抽定，**玩家和 Ghost 抽到的是同一个数**——运气不制造对照差异，差异只来自选择。
- **部分收益延后揭晓**：成果是累积制，攒够门槛才算成立。中途看不到「还差几点就一定成」。
- **题数未知**：不知道还剩几步，「留一手」和「现在就花」之间永远有张力。

## 每局会变的东西

| 维度 | 取值 |
| --- | --- |
| 灾种 | 地震 / 洪水 / 火灾 / 泥石流 / 台风 / 雪崩 |
| 信号 | 时断时续 / 微弱 / 完全中断 / 局部可用 |
| 伤势 | 暂无 / 擦伤 / 疑似骨折 / 持续失血 |
| 温度 | 严寒 / 阴凉 / 闷热 / **炎热** |
| 时段 | 白天 / 黄昏 / 深夜 |
| 随身 | 两手空空 / 有纸笔 / 有手电 / 有残电充电宝 |
| 题数 | 8 ~ 12（本局编号决定，界面不显示） |
| 你的天赋 | 12 个里随机抽 3 个，三选一 |
| Ghost 性格 | 急性子 / 守财奴 / 赌一把 / 老好人 / 稳妥派 / 领头的 |
| Ghost 天赋 | 12 个里随机 1 个 |

天赋四类：打折（某类标签耗电降低）、加成（某类成果每次多得 1 点）、护盾（严寒或有伤时全局减耗）、回充（等待类选项反而回 0.015%）。

Ghost 的性格是**加权打分**，不是最优解：急性子看见就办，守财奴只挑便宜的，稳妥派一律绕开带「不确定」的选项。换一个性格，同样的题目就是另一种人生。

同一情境的题干有 2 套措辞，开局背景有 6×2 种处境说法，都由本局编号决定；规则不变，读法不同。

## 操作方式

除点击外，事件页可用数字键 1–9 选择对应选项。每个选项标注**实际耗电**（已按当前环境折算）、**权重档位**和「做完还剩多少电」。正文正在逐字显示时，点正文或「跳过这段」可立刻看完整段；系统开启「减少动态效果」时打字动画自动关闭。

结算页一进来就滚到顶部——结果在最上面，不能让人停在最下面。复盘表格默认折叠，想看再展开。

## 数据与规则

- 存活概率：见上文公式，三个因子各自可解释，常量都在 `src/game/config.ts` 的 `SURVIVAL` 里，可复算。
- 存档只在浏览器本地，schema 3；损坏记录不加载、可导出备份。导出 JSON 含编号、规则版本、动作与结果，可由 `verifyExport` 重算回来。
- 相同编号与版本复现同一世界；行动数量不改变随机环境。局内看不到 Ghost 未来的动作，它只同步到前一步；结算时补全最后一步。
- 旧口径的分数（`scoreOf`）保留用于历史记录，不再作为结算结论。

所有能耗、概率、环境和人物为模拟，非实际电量测量或救援指导。3–5 分钟是体验目标。

## 结构

`src/game/` 为纯规则与记录：`config.ts`（数值与存活模型）、`world.ts`（抽世界与题数）、`engine.ts`（成本、自然损耗、收益）、`oracle.ts`（事后最优参考线）、`ghost.ts`（镜像）、`replay.ts`（流程与回放）、`scoring.ts`（贡献与存活概率）、`rng.ts`（确定性随机）。
`src/game/content/` 为素材：`questions.ts` + `bank/`（130 道题）、`talents.ts`（12 个天赋）、`personas.ts`（6 种性格）、`backdrop.ts`（开局处境）。
`src/components/` 为页面（`SurvivalChart.tsx` 画三条曲线，`useTypewriter.ts` 管逐字显示），`tests/game.spec.ts` 是浏览器流程验收。
测试另有 `bank.test.ts`（题库体检）、`balance.test.ts`（平衡性与存活概率梯度）、`core.test.ts`（规则）。

使用 React、Vite、TypeScript、Vitest 和 Playwright，版本固定在 package-lock.json；保留各依赖许可证。视觉图形由 CSS 与内联 SVG 绘制，无第三方图片。开发由 AI 辅助，规则取舍与测试结果见项目设计文档与提交历史。

v0.1 为开发前设计基线；v0.1.0 为可玩首版（时间轴制）；v0.2.0 改为抽题制 roguelike；**v0.3.0 加入时间轴（每步 15 分钟）、自然损耗、环境耗电耦合、存活概率评分、权重档位与事后最优曲线**。尚未获得比赛评分或真人试玩验证。
