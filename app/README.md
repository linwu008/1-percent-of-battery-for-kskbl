# 1% Battery · v0.2.0

灾后资源决策模拟器。手机只剩 **1.000%** 电量，你要在十道题里决定这些电花在哪儿。
每题都有标价（0.0xx% ~ 0.2xx%），同一件事在不同灾难、网络、伤势下值不值，答案不一样。
局内有一个和你抽同一批题的 **Ghost**，它有自己的性格与天赋，不是标准答案；结算时逐题对照，看你的取舍值不值。

正文逐字打字显示。打字不推进进度、不耗电——阅读和思考是免费的。

## 启动

需要 Node.js 24 或更新的兼容版本。测试环境为 Node 24.20.0、Windows、Edge。

```powershell
cd app
npm ci
npm run dev
```

浏览器打开终端给出的本地地址，默认 http://127.0.0.1:5173 。运行无需云 API、账号、定位或真实短信权限。依赖首次安装需要网络。

## 一局怎么走

1. **开局简报**：先看到这局的世界（灾种 / 信号 / 伤势 / 温度 / 时段 / 随身），以及随机抽到的 **三个天赋，三选一**。
2. **十道题**：早期 3 道、中期 4 道、后期 3 道，从 **130 道题库**里按本局编号（seed）抽取。同一编号必然抽到同一组题。
3. **结算**：成果对照、逐题复盘、公式、导出 JSON。

固定案例用于演示与回归：**案例 A**（局部有网、擦伤、深夜、有纸笔）、**案例 B**（彻底断网、持续失血、严寒、两手空空）。案例连题目顺序都固定，所以演示和比较能对得上。

## 电量为什么是真约束

电量内部以 **0.001%** 记账，满值 1000 = 屏幕上的 1.000%。选项标价从 0 到 260 不等。

六类成果各有**门槛**（位置 4 点 / 人数 2 点 / 光信号 3 点 / 传达 2 点 / 回联 4 点 / 接力 3 点），门槛刻意高于「一次不耗电的口头或敲击操作能拿到的点数」——否则全靠免费选项就能凑齐成果，1% 就成了摆设。

成果价值上限 **12 分权重**，而总电量只有 1.000%。全做到，物理上不可能。

实测（60 个种子 × 三种典型打法）：

| 打法 | 成果均值（上限 12） | 均分 | 平均耗电 | 满值局数 |
| --- | --- | --- | --- | --- |
| 激进（每步挑最高收益） | 5.6（2~9） | 63.4 | 824.5 / 1000 | 0 |
| 保守（每步挑最便宜） | 3.7（0~8） | 48.9 | 204.9 / 1000 | 0 |
| 性价比（单位电量收益最高） | 3.9（0~8） | 50.3 | 230.2 / 1000 | 0 |

**没有一种打法能拿满，也没有一种打法通吃**：激进赢保守的局数和保守赢激进的局数都大于零。十道题全走最贵的路，超过一半的局会在中途破产。

## 为什么没有唯一最优解

三件事同时作用，让「最佳选项」不成立：

- **环境耦合**：同一个选项带 `env` 规则，在世界满足某个条件时收益增减。断网时"再发一次短信"是纯浪费，局部有网时它是救命的一步。题库里带环境修正的选项占比有测试兜底。
- **条件收益与赌运**：带「不确定」标签的选项成败由本局编号预先抽定，**玩家和 Ghost 抽到的是同一个数**——运气不制造对照差异，差异只来自选择。
- **部分收益延后揭晓**：成果是累积制，攒够门槛才算成立。中途看不到"还差几点就一定成"，只能按当前世界判断值不值。

## 每局会变的东西

| 维度 | 取值 |
| --- | --- |
| 灾种 | 地震 / 洪水 / 火灾 / 泥石流 / 台风 / 雪崩 |
| 信号 | 时断时续 / 微弱 / 完全中断 / 局部可用 |
| 伤势 | 暂无 / 擦伤 / 疑似骨折 / 持续失血 |
| 温度 | 严寒 / 阴凉 / 闷热 |
| 时段 | 白天 / 黄昏 / 深夜 |
| 随身 | 两手空空 / 有纸笔 / 有手电 / 有残电充电宝 |
| 你的天赋 | 12 个里随机抽 3 个，三选一 |
| Ghost 性格 | 急性子 / 守财奴 / 赌一把 / 老好人 / 稳妥派 / 领头的 |
| Ghost 天赋 | 12 个里随机 1 个 |

天赋四类：打折（某类标签耗电降低）、加成（某类成果每次多得 1 点）、护盾（严寒或有伤时全局减耗）、回充（等待类选项反而回 0.015%）。

Ghost 的性格是**加权打分**，不是最优解：急性子看见就办（赌运权重高、怕贵权重低），守财奴只挑便宜的，稳妥派一律绕开带「不确定」的选项。换一个性格，同样的题目就是另一种人生。

同一情境的题干有 2 套措辞，由本局编号决定用哪一套；规则不变，读法不同。

## 操作方式

除点击外，事件页可用数字键 1–9 选择对应选项，便于演示时快速推进。每个选项标注标价与**做完还剩多少电**。正文正在逐字显示时，点正文或「跳过这段」可立刻看完整段；系统开启「减少动态效果」时打字动画自动关闭。

电量归零也不卡死：题库保证每道题至少有一个 0 成本选项；真的一分不剩时会出现「攥着手机，什么也做不了」的放弃通道，把剩下的题空过去直接结算（有测试覆盖）。

## 数据与规则

- 分数：**成果优先，余量其次**。`分数 = 11 × 成果价值 + 剩余电量百分比 × 10`；成果为 0 时记为 0 分，避免宣传「什么都不做最省电」。
- 存档只在浏览器本地；损坏记录不加载。导出 JSON 含编号、规则版本、动作与结果，可由 `verifyExport` 重算回来。
- 相同编号与版本复现同一世界；行动数量不改变随机环境。局内看不到 Ghost 未来的动作，它只同步到前一题。

所有能耗、环境和人物为模拟，非实际电量测量或救援指导。3–5 分钟是体验目标。

## 结构

`src/game/` 为纯规则与记录：`config.ts`（数值）、`world.ts`（抽世界）、`engine.ts`（成本与收益）、`ghost.ts`（镜像）、`replay.ts`（流程与回放）、`scoring.ts`（评分）、`rng.ts`（确定性随机）。
`src/game/content/` 为素材：`questions.ts` + `bank/`（130 道题）、`talents.ts`（12 个天赋）、`personas.ts`（6 种性格）。
`src/components/` 为页面，`tests/game.spec.ts` 是浏览器流程验收。
测试另有 `bank.test.ts`（题库体检：编号不重复、必有免费选项、环境维度真实存在、六类成果都可达）与 `balance.test.ts`（平衡性）。

使用 React、Vite、TypeScript、Vitest 和 Playwright，版本固定在 package-lock.json；保留各依赖许可证。视觉图形由 CSS 绘制，无第三方图片。开发由 AI 辅助，规则取舍与测试结果见项目设计文档与提交历史。

v0.1 为开发前设计基线；v0.1.0 为可玩首版（时间轴制）；**v0.2.0 改为抽题制 roguelike**，取消时间轴，改由 1% 电量与十道题构成约束。尚未获得比赛评分或真人试玩验证。
