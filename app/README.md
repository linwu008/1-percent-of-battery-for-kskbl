# 1% Battery · v0.5.0

v0.5.0 基于 v0.4.0（682f81f）改造前端：原创灾后终端视觉、中央逐字剧情、选择后确认、底部资源与操作栏、Ghost 镜像。游戏引擎和规则版本仍为 0.4.0，旧存档继续兼容。

操作：点击或数字键选中，确认按钮执行。↑↓ 切换，Enter 在逐字时只补全文字，读完后再次按下才确认；Escape 清除选择。已知信息与行动记录不推进时间。可开启立即显示，支持系统减少动效设置。界面仅参考叙事交互与设计语言，未使用商业游戏素材或第三方游戏源码。

灾后资源决策模拟器。手机只剩 **1.000%** 电量，你要在 **8~12 步**（具体几步不告诉你）里决定这点电花在哪儿。
每一步固定推进 **15 分钟**——就算你什么都不做，电池也在自己往下掉。
结算不再给分数，而是给一个**存活概率**：你有多大可能被找到、被救出、并且撑到那一刻。

v0.4.0 的核心变化：**权重分成两层，而且两层都藏起来**。每个动作有一档（这个动作本身有多重），
每道题也有一档（这一题在整条救援链上有多关键）。过程中什么都不告诉你——
哪一步真正关键，得你自己判断；结算时全部摊开，可以复算。

## 一局怎么走

1. **先看清处境**：开局逐字打出这一局的灾难现场——发生了什么、天亮不亮、身上有没有伤、有没有纸笔、信号还在不在，最后讲清楚任务是什么。测试玩家看不懂题，多半不是题难，是不知道自己站在哪儿。
2. **选天赋**：看到本局的世界（灾种 / 信号 / 伤势 / 温度 / 时段 / 随身），再从随机抽到的三个天赋里三选一。
3. **走 8~12 步**：从 **130 道题库**里按本局编号（seed）抽取，早 / 中 / 晚三段分配。界面只显示「第 n 步」，不显示总数。
4. **结算**：存活概率、三条曲线、权重贡献、完整公式、逐题复盘、导出 JSON。

中途随时可以**放弃这一局并重开**，本局不计入记录。

固定案例用于演示与回归：**案例 A**（局部有网、擦伤、深夜、有纸笔，9 步）、**案例 B**（彻底断网、持续失血、严寒、两手空空，11 步）。案例连题目顺序都固定，所以演示和比较能对得上。

## 电量是变量，不是常量

电量内部以 **0.001%** 记账，满值 1000 = 屏幕上的 1.000%。选项标价 0~260，但**实际耗电会被环境改写**：

```
实际耗电 = 名义标价 × 环境倍率 × 1.3（整体倍率），再算天赋折扣
环境倍率 = 温度系数（阴凉 1.00 / 闷热 1.10 / 严寒 1.15 / 炎热 1.25）
          × 信号系数（仅亮屏类：局部 1.00 / 微弱 1.15 / 时断时续 1.20 / 断网 1.30）
```

**自然损耗**：每一步 15 分钟，电池固定掉一格，不操作也掉：

```
每步自然损耗 = 14 × 温度系数 × 信号系数
温度：阴凉 1.00 / 闷热 1.15 / 严寒 1.30 / 炎热 1.55
信号：局部 1.00 / 微弱 1.20 / 时断时续 1.35 / 断网 1.45
```

炎热 + 断网是最狠的组合——每步自然就掉 31 格（0.031%），什么都不做，十步之后一半的电就没了。

电量归零后，**不耗电的选项仍然选得动**，但拿到的都是些小成果；想再做什么大动作就没门了。这是设计好的：破产不是死局，是只剩小动作。

六类成果各有**门槛**（位置 4 / 人数 2 / 光信号 3 / 传达 2 / 回联 4 / 接力 3），门槛刻意高于「一次不耗电操作能拿到的点数」——否则全靠免费选项就能凑齐成果，1% 就成了摆设。

## 存活概率：三段相乘

分数换成了概率，因为「省电胜利」这件事不值得宣传，而「活下来的可能性」才是这批决策真正的产出。

```
P(存活) = P(被发现) × P(被救出) × P(撑到救援)

P(被发现) = 0.21 + 0.87 ×（被发现贡献 ÷ 11），上限 0.95
P(被救出) = 0.24 + 0.85 ×（被救出贡献 ÷ 7.5），上限 0.95
P(撑到救援) = 0.78 + 0.42 × 剩余电量比例 − 0.009 × 已走步数
              − 伤势惩罚 − 温度惩罚 − 关机惩罚（电量归零 0.15），下限 0.03
```

伤势惩罚：无 0 / 擦伤 0.018 / 疑似骨折 0.05 / 持续失血 0.10。
温度惩罚：阴凉 0 / 闷热 0.012 / 炎热 0.035 / 严寒 0.055。

三个常量由离线标定得出（60 种子 × 4 种打法 + 事后最优），目标是**事后最优落在 70% 左右**——
理论上限够高，玩家才有往上够的余地；同时三段各自都有余量，没有任何一段被压死。

前两段的「贡献」怎么算，就是**两层权重**：

```
每一步的贡献 = 该成果的实际点数 × 动作档位倍率 × 题目权重倍率
被发现贡献 = Σ（位置送达 / 光信号起作用 / 人数送达 的点数 × 两层倍率）
被救出贡献 = Σ（安排已传达 / 回联确认 / 接力送达 的点数 × 两层倍率）
```

| 动作档位 | 倍率 | 判定（题库没写档位时的默认规则） |
| --- | --- | --- |
| 最重要 | ×3 | 名义成本 ≥ 110，且有收益 |
| 较重要 | ×2 | 名义成本 1~109，且有收益 |
| 不重要 | ×1 | 完全不耗电，或压根没有收益 |

| 题目权重 | 倍率 | 来源 |
| --- | --- | --- |
| 最重要 | ×1.5 | 本局抽到，约占三成 |
| 较重要 | ×1.2 | 本局抽到，约占三成半 |
| 不重要 | ×1.0 | 本局抽到，其余 |

题目权重的倍率刻意**比动作档位温和**（1.5/1.2/1.0 而不是 3/2/1）：具体动作的分量应该盖过题目本身的分量，
否则玩家会觉得「输在抽题」而不是「输在判断」。每局的题目权重由世界编号抽定，
**同一道题在这一局是关键题，在下一局可能只是铺垫**——这是随机性的来源之一，也有测试兜底
（每局至少一道关键题；同一道题必须在多档里都出现过）。

两层权重**在游戏过程中完全不显示**：选项上没有档位标签，题干区也没有题目权重。
结算页才揭晓——动作档位表、题目权重表、逐题对照表（每一道都标出它的权重与你在它上面拿到的贡献），
外加完整公式。

同样 2 点：一个「不重要」的动作落在「不重要」的题上算 2 × 1 × 1.0 = 2 分；
若是「最重要」的动作落在「最重要」的关键题上，算 2 × 3 × 1.5 = 9 分——差 4.5 倍。

## 三条曲线：你偏离在哪一步

结算页画一张弧线图，三条线同屏：

- **事后最优**（虚线）：知道本局全部赌运之后能达到的理论上限，由定向搜索（beam 20 × 三个天赋）算出。**它不是标准答案**——当时没人知道那些信息。它的唯一作用是让人看见自己哪一步偏了，并标出偏离最多的那一步。
- **你**：每一步结束时的存活概率。
- **Ghost**：同批题、同赌运、按性格花钱的另一条路。

纵轴是「按当时手上的东西算，能活下来的概率」，两条线之间的落差就是那一步的选择造成的偏差。

## 实测（60 个种子 × 三种典型打法）

| 打法 | 存活概率均值 | 区间 | 被发现 | 被救出 | 撑到救援 | 结束时剩余电量 |
| --- | --- | --- | --- | --- | --- | --- |
| 激进（每步挑最高收益） | 42.7% | 10.2 ~ 65.8% | 94.9% | 84.5% | 52.9% | 19 / 1000 |
| 保守（每步挑最便宜） | 56.7% | 15.7 ~ 79.7% | 88.1% | 83.5% | 78.7% | 415 / 1000 |
| 性价比（单位电量收益最高） | 55.8% | 15.7 ~ 79.7% | 87.9% | 84.5% | 77.0% | 387 / 1000 |
| **事后最优参考线** | **70.6%** | 18.9 ~ 84.5% | — | — | — | — |
| 什么都不做 | 4.7% | 4.0 ~ 4.8% | 21.0% | 24.0% | 92.7% | 770 / 1000 |

读数：激进派把成果拉满（被发现贡献 22.9）但把电烧光，第三段「撑到救援」只剩 52.9%，
这正是它落后保守派的原因。保守派和性价比派活得更久，但前两段的贡献较低——**三段互相拉扯，没有白拿的**。
两者都拿不到满值成果，也都没有一种打法通吃。事后最优 70.6% 与保守派 56.7% 之间有约 14 个百分点的空间，
那是「知道全部赌运之后」才够得着的部分。

题数在 8~12 上分布均匀（60 局：8 题 9 局 / 9 题 17 局 / 10 题 11 局 / 11 题 11 局 / 12 题 12 局）。

## 为什么没有唯一最优解

- **环境耦合**：同一个选项带 `env` 规则，世界满足某条件时收益增减。断网时「再发一次短信」是纯浪费，局部有网时它是救命的一步。题库里带环境修正的选项占比有测试兜底。
- **条件收益与赌运**：带「不确定」标签的选项成败由本局编号预先抽定，**玩家和 Ghost 抽到的是同一个数**——运气不制造对照差异，差异只来自选择。
- **部分收益延后揭晓**：成果是累积制，攒够门槛才算成立。中途看不到「还差几点就一定成」。
- **题数未知**：不知道还剩几步，「留一手」和「现在就花」之间永远有张力。

## 每局会变的东西

| 维度 | 取值 |
| --- | --- |
| 灾种 | 地震 / 洪水 / 火灾 / 泥石流 / 台风 / 雪崩 |
| 信号 | 时断时续 / 微弱 / 完全中断 / 局部可用 |
| 伤势 | 暂无 / 擦伤 / 疑似骨折 / 持续失血 |
| 温度 | 严寒 / 阴凉 / 闷热 / **炎热** |
| 时段 | 白天 / 黄昏 / 深夜 |
| 随身 | 两手空空 / 有纸笔 / 有手电 / 有残电充电宝 |
| 题数 | 8 ~ 12（本局编号决定，界面不显示） |
| 题目权重 | 每道题独立抽定（关键 / 较重要 / 不重要），过程中不显示 |
| 你的天赋 | 12 个里随机抽 3 个，三选一 |
| Ghost 性格 | 急性子 / 守财奴 / 赌一把 / 老好人 / 稳妥派 / 领头的 |
| Ghost 天赋 | 12 个里随机 1 个 |

天赋四类：打折（某类标签耗电降低）、加成（某类成果每次多得 1 点）、护盾（严寒或有伤时全局减耗）、回充（等待类选项反而回 0.015%）。

Ghost 的性格是**加权打分**，不是最优解：急性子看见就办，守财奴只挑便宜的，稳妥派一律绕开带「不确定」的选项。换一个性格，同样的题目就是另一种人生。

同一情境的题干有 2 套措辞，开局背景有 6×2 种处境说法，都由本局编号决定；规则不变，读法不同。

## 操作方式

除点击外，事件页可用数字键 1–9 选择对应选项。每个选项标注**实际耗电**（已按当前环境折算）和「做完还剩多少电」——
**不标权重**，那是要判断的部分。正文正在逐字显示时，点正文或「跳过这段」可立刻看完整段；
系统开启「减少动态效果」时打字动画自动关闭。

结算页一进来就滚到顶部——结果在最上面，不能让人停在最下面。复盘表格与逐题对照默认折叠，想看再展开。

## 数据与规则

- 存活概率：见上文公式，三个因子各自可解释，常量都在 `src/game/config.ts` 的 `SURVIVAL` 里，可复算。
- 权重有两层：`TIER_WEIGHT`（动作）与 `QUESTION_WEIGHT`（题目，含每局配额 `QUESTION_WEIGHT_MIX`），都在 `config.ts`。
- 存档只在浏览器本地，schema 4；损坏记录不加载、可导出备份。导出 JSON 含编号、规则版本、动作与结果，可由 `verifyExport` 重算回来。
- 相同编号与版本复现同一世界；行动数量不改变随机环境。局内看不到 Ghost 未来的动作，它只同步到前一步；结算时补全最后一步。
- 旧口径的分数（`scoreOf`）保留用于历史记录，不再作为结算结论。

所有能耗、概率、环境和人物为模拟，非实际电量测量或救援指导。3–5 分钟是体验目标。

## 结构

`src/game/` 为纯规则与记录：`config.ts`（数值、两层权重与存活模型）、`world.ts`（抽世界、题数与题目权重）、`engine.ts`（成本、自然损耗、收益）、`oracle.ts`（事后最优参考线）、`ghost.ts`（镜像）、`replay.ts`（流程与回放）、`scoring.ts`（贡献与存活概率）、`rng.ts`（确定性随机）。
`src/game/content/` 为素材：`questions.ts` + `bank/`（130 道题）、`talents.ts`（12 个天赋）、`personas.ts`（6 种性格）、`backdrop.ts`（开局处境）。
`src/components/` 为页面（`SurvivalChart.tsx` 画三条曲线，`useTypewriter.ts` 管逐字显示），`tests/game.spec.ts` 是浏览器流程验收。
测试另有 `bank.test.ts`（题库体检）、`balance.test.ts`（平衡性与存活概率梯度）、`core.test.ts`（规则）。

使用 React、Vite、TypeScript、Vitest 和 Playwright，版本固定在 package-lock.json；保留各依赖许可证。视觉图形由 CSS 与内联 SVG 绘制，无第三方图片。开发由 AI 辅助，规则取舍与测试结果见项目设计文档与提交历史。

v0.1 为开发前设计基线；v0.1.0 为可玩首版（时间轴制）；v0.2.0 改为抽题制 roguelike；
v0.3.0 加入时间轴（每步 15 分钟）、自然损耗、环境耗电耦合、存活概率评分、权重档位与事后最优曲线；
**v0.4.0 把权重拆成「动作 + 题目」两层并全部藏到结算之后，同时重新标定概率模型，把事后最优拉回 70% 左右**。
尚未获得比赛评分或真人试玩验证。
