# v1.0.0 交付说明

## 本轮定位

**交付定稿版。游戏规则与界面和 v0.7.0 完全一致，未改动任何玩法数值**  
（规则版本仍为 0.6.0）。本版只做三件事：把对外文档补全、补齐界面素材、修一条测试缺陷。

## 本轮修改

### 1. 根 README 重写（本轮主要产出）

原根 README 停在 v0.4.0，队友在 v0.5~v0.7 期间只更新了 `app/README.md`，  
仓库首页展示的是三个月前的版本说明。本次整篇重写，补齐六块内容：

- **项目解释**：这是什么、为什么用存活概率而不是分数、Ghost 到底代表什么。
- **操作说明**：进入 → 看处境 → 选策略 → 每步选择 → 看结算 → 重开，  
  六个步骤各配一张真实界面截图；键盘操作（1–4 / 方向键 / Enter / Escape）也写清楚。
- **规则与数值**：电量记账单位、行动耗电与环境耦合、自然损耗、每步时长、  
  两层权重（动作档位 × 题目权重）与完整的三段存活概率公式。
- **切题说明**（本次新增的重点）：
  - 赛题要求逐项对应表（资源约束 / 对比数据 / 相近作品 / 差异主张 / 可交互 / 模拟声明 / 设计决策）；
  - 与两个最相近作品的差别（《人生重开模拟器》按属性驱动 vs 本项目按可计量成本驱动；  
    厂商「1% 应急模式」系统替用户省电 vs 本项目让用户自己决定怎么花）；
  - 三条可当场验证的差异主张（成本是算出来的、对照是同环境实时的且 Ghost 非最优、  
    每份消耗可追溯到成果）；
  - 「哪些是模拟」的明确声明：不修改设备设置、不产生真实省电效果，  
    厂商数据不得写成我们的实测。
- **用数据说明表现**：当前版本实测表（见下）。
- **技术实现与版本沿革**：目录结构、确定性种子机制、测试与验证方法、  
  v0.1.0 → v1.0.0 每一版的关键变化。

### 3. 测试缺陷修复

`balance.test.ts` 的「事后最优落在 70% 上下」一条依赖 vitest 默认的 5 秒超时，   
但它要跑 40 个种子 × beam 搜索，本机实测 6.9 秒，**必然超时**。  
这在我这台机器上表现为 `npm test` 失败（81 项中 1 项），不是游戏逻辑问题。  
已单独把该条超时放宽到 60 秒，并加了注释说明**不要靠调小种子数来让它变快**。
