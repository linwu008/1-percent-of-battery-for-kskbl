**日期**：2026-10-13

## 一、这是什么

一段 **2 分 54 秒**的作品演示视频，内容是从封面到结算的**完整一局实机录制**，
不做剪辑拼接。用途：提交材料里的演示件、presentation 前的自检与预热。

| 项 | 值 |
| --- | --- |
| 时长 | 2:54.24（正片 2:48 + 片尾卡 6 秒） |
| 分辨率 | 1440 × 988（画面 1440×900 + 底部 88px 字幕栏） |
| 编码 | H.264 High / yuv420p / 25fps / 无音轨 |
| 体积 | 8.2 MB |

**时间轴**（字幕栏分段）：

| 时间 | 内容 |
| --- | --- |
| 0:00 | 封面「最后的余量」 |
| 0:09 | 主页：玩法说明与 Ghost 世界镜像 |
| 0:17 | 序章：处境逐字打出（**不跳过**，这是招牌交互） |
| 0:36 | 策略三选一 |
| 0:50 | 局内：逐步决策（第 1–3 步完整展示，其余加速） |
| 1:59 | 结算：存活概率与三段分解 |
| 2:05 | 逐步曲线：你 / Ghost / 事后最优 |
| 2:21 | 权重揭晓：动作档位 × 题目权重 |
| 2:48 | 片尾卡：在线链接与源码仓库 |

## 二、怎么做的

三步，都可复现：

```sh
cd app

# 1) 录屏（约 3 分钟）
#    首次需要 Playwright 自带的 ffmpeg：npx playwright install ffmpeg
RECORD_DEMO=1 npm run test:browser -- tests/demo.spec.ts

# 2) 录完立刻把源文件挪出 test-results（原因见「坑 2」）
mkdir -p .demo-work
find test-results -name video.webm -exec cp {} .demo-work/source.webm \;

# 3) 转码：加字幕栏与片尾卡
python scripts/make-demo-video.py
```

`tests/demo.spec.ts` 本身**默认跳过**（`test.skip(!process.env.RECORD_DEMO, ...)`），
不设环境变量时不影响常规回归——实测 `npm run test:browser` 为 27 passed / 1 skipped。

### 三条设计决定

**1. 节奏跟着页面状态走，不硬编码等待时间。**
脚本推进的判据全是页面上的真实状态：等「继续 · 选择策略」从 disabled 变可点
（说明序章的打字机打完了）、等 `[data-testid=battery]` 的读数真的变化
（说明这一次确认生效了）。所以界面改了、文案长了短了，脚本照样对得上，
不会录出一堆空等或者半截画面。

**2. 注入一个跟随鼠标的光标。**
Playwright 录的视频流里**没有系统光标**，观众会看到选项"自己就选中了"。
所以在页面里注入一个 `pointer-events: none` 的圆环跟随 `mousemove`，
点击时收缩变色。它只影响观感，不参与任何选择器。

**3. 案例 A 的步数不写死。**
循环条件写成「一直走，直到结算页出现为止」，而不是 `for i < 9`。
规则一旦调整步数，脚本不需要跟着改。

### 字幕时间轴怎么来的

录屏脚本在每个阶段开始时记下相对时间，写在 `assets/demo-cues.json`；
转码脚本再把它们整理成 ffmpeg 的 `drawtext` 时间区间。

**不要改成手工估算的时间轴。** 各阶段耗时本来就是被打字机速度、
页面状态牵着走的，每一遍录都不一样（实测两次录制在第 5 条提示上差了 16 毫秒，
但打字机段落会随文本长度浮动几秒）。用录制时的真实时间戳才不会错位。

## 三、踩到的坑

**坑 1：本机没有 Playwright 自带的 ffmpeg。**
Playwright 用系统 Edge（`channel: "msedge"`）所以从没下载过浏览器包，
`ms-playwright` 目录不存在，录屏直接报
`Executable doesn't exist at ...\ffmpeg-1013\ffmpeg-win64.exe`。

正解是 `npx playwright install ffmpeg`。本次为了不依赖网络，
改用 `pip install imageio-ffmpeg` 自带的完整 ffmpeg 7.1 静态构建，
复制到 Playwright 期望的路径顶替（已验证支持 libvpx 与 libx264）。
**换机器时请优先用官方的 `npx playwright install ffmpeg`。**

**坑 2：跑完整测试会清掉录屏。**
Playwright 默认只保留失败用例的产物，`npx playwright test` 一跑，
`test-results/` 连同 `video.webm` 一起没了。所以流程里必须
**录完立刻复制到 `.demo-work/source.webm`**，转码脚本优先读这个位置。

**坑 3：`.skip-type` 在剧情打完时是 disabled。**
"跳过这段"按钮的 `disabled={typed.done}`——剧情读完后它就点不动了。
脚本里直接 `click()` 会一直等它变可点，直到超时。
正确写法是先判断 `isEnabled()` 再决定点不点。

**坑 4：`"行动"` 三个字会撞三个按钮。**
底栏标签里「行动」是「行动记录」的前缀，文案里还有「剧情已显示 · 请选择行动」。
Playwright 严格模式会直接报错。改用精确属性选择器
`.command-tabs button[aria-label="行动"]`。

**坑 5：确认后不一定还剩在本局。**
最后一步确认完直接进结算页，`[data-testid=battery]` 会消失。
断言写成「电量变了 **或** 结算页出现了」二者其一，否则最后一步必然超时。

## 四、待办

- **界面版本号与交付版本号不一致**：界面右上角与封面底部显示的是 `v0.7.0`
  （v1.0.0 分支按需求只改了文档与素材，没动代码）。视频与片尾卡都按 v1.0.0 标注。
  若要统一，需要改界面文案并重新录屏、重新部署。
- 动图与视频都没有做自动化，界面大改后需要手动重跑上文的第 1–3 步。
- 视频无音轨。若 presentation 需要配乐或旁白，建议在最终剪辑时叠加，不要改源片。
